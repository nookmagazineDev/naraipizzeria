# เข้าสู่ระบบ และสิทธิ์ผู้ใช้รายคน

แดชบอร์ดนี้เคยเปิดเข้าได้เลยโดยไม่ต้องล็อกอิน (แถบข้างเขียนตายไว้ว่า “ผู้ใช้งาน: magazine”)
ตอนนี้ต้องล็อกอินก่อน และแต่ละบัญชีเห็นเฉพาะเมนูที่ผู้ดูแลระบบเปิดสิทธิ์ให้

## ของอยู่ตรงไหน

| ไฟล์ | หน้าที่ |
|---|---|
| `lib/permissions.js` | ทะเบียนเมนู/คีย์สิทธิ์ + กติกา `hasPerm` — ใช้ร่วมกันทั้งหน้าเว็บและ API |
| `lib/authToken.js` | ออก/ตรวจตั๋วเข้าระบบ (HMAC-SHA256 ในคุกกี้ `narai_session`) |
| `lib/authUsers.js` | คลังผู้ใช้บน SQL + เข้ารหัสผ่านด้วย scrypt (ฝั่งเซิร์ฟเวอร์เท่านั้น) |
| `pages/api/auth.js` | เข้าสู่ระบบ / ออกจากระบบ / เปลี่ยนรหัสผ่านตัวเอง |
| `pages/api/users.js` | เพิ่ม-แก้-ลบผู้ใช้ และตั้งสิทธิ์ (ผู้ดูแลระบบเท่านั้น) |
| `middleware.js` | ด่านหน้า `/api/*` — ไม่มีตั๋ว = ไม่ได้ข้อมูล |
| `components/LoginPage.jsx` | หน้าล็อกอิน |
| `components/UserList.jsx` | หน้า “ระบบ → จัดการผู้ใช้และสิทธิ์” |
| `docs/schema-app-user.sql` | ตาราง `InventoryNarai.dbo.app_user` + บัญชี admin ตั้งต้น |

## สิทธิ์ทำงานยังไง

สองชั้น:

1. **ล็อกอินหรือยัง** — `middleware.js` ตรวจตั๋วก่อนถึง `/api/*` ทุกเส้น (ยกเว้น `/api/auth`)
   ไม่มีตั๋วได้ 401 กลับไป ไม่ว่าจะยิงจากหน้าเว็บหรือเปิด URL ตรง ๆ
2. **เห็นเมนูไหน** — `hasPerm(user, key)` ใน `lib/permissions.js` ตัดสินว่าเมนูไหนถูกวาดในแถบข้าง
   และหน้าไหนเปิดได้ · `role='admin'` เห็นทุกเมนูเสมอ · `/api/users` เช็กบทบาทซ้ำในตัวเอง

> ⚠️ ชั้นที่ 2 คุมแค่ “เห็นเมนูไหน” ไม่ได้ผูกเส้น API กับคีย์เมนู เพราะ API หลายเส้นถูกใช้ร่วมกัน
> หลายหน้า (เช่น `/api/branches` เติม dropdown แทบทุกหน้า) คนที่ล็อกอินแล้วและรู้ชื่อเส้น API
> ยังยิงเอาข้อมูลของเมนูที่ตัวเองไม่ได้สิทธิ์ได้อยู่ · จะปิดช่องนี้ต้องผูกสิทธิ์ลงราย endpoint
> ซึ่งยังไม่ได้ทำในรอบนี้

## ตั้งค่าครั้งแรก

1. เปิดเว็บ จะเจอหน้าล็อกอินพร้อมแถบแดง “โหมดตั้งค่า”
2. เข้าด้วย **`admin` / `admin1234`** (ใช้ได้เฉพาะตอนที่ยังไม่มีคลังผู้ใช้จริง)
3. ไปเมนู **ระบบ → จัดการผู้ใช้และสิทธิ์** กดปุ่ม **สร้างตาราง**
   (หรือรัน `docs/schema-app-user.sql` ที่เครื่องออฟฟิศด้วย sqlcmd / SSMS)
4. **เปลี่ยนรหัสผ่านของ `admin` ทันที** ที่ปุ่ม “เปลี่ยนรหัสผ่าน” ท้ายแถบข้าง
5. เพิ่มผู้ใช้ที่เหลือ แล้วติ๊กเมนูให้ทีละคน

พอตารางมีแล้ว โหมดตั้งค่าจะปิดเอง — `admin1234` ใช้ไม่ได้อีกนอกจากยังไม่ได้เปลี่ยนรหัสในฐาน

## ค่า env บน Vercel

| ตัวแปร | จำเป็นไหม | ทำอะไร |
|---|---|---|
| `AUTH_SECRET` | **ควรตั้ง** | กุญแจเซ็นตั๋ว · ไม่ตั้งจะถอยไปใช้ `QCRD_DB_PASSWORD` / `ZK_DB_PASSWORD` / `HR_DB_PASSWORD` · ไม่มีสักตัวจะใช้กุญแจตั้งต้นซึ่ง **ปลอมตั๋วได้** และหน้าเว็บจะขึ้นแถบเตือน · ตั้งเป็นข้อความสุ่มยาว ๆ (เปลี่ยนค่านี้ = ทุกคนต้องล็อกอินใหม่) |
| `QCRD_DB_USER` / `QCRD_DB_PASSWORD` | ต้องมีถ้าจะเก็บผู้ใช้ลงฐาน | ตัวเดียวกับที่ QC/RD และทะเบียนสาขาใช้ (`ZK_DB_*` / `HR_DB_*` ก็ได้ ถ้ามีสิทธิ์ใน `InventoryNarai`) |
| `APP_ADMIN_USER` / `APP_ADMIN_PASSWORD` | ไม่บังคับ | ผู้ดูแลสำรองหนึ่งคนที่ไม่ต้องพึ่งฐาน — ต่อ SQL ไม่ติดก็ยังเข้าไปดูได้ว่าเกิดอะไรขึ้น · ตั้งไว้แล้วโหมดตั้งค่าจะปิดทันที |
| `AUTH_DISABLED=1` | ทางออกฉุกเฉิน | ปิดด่าน `/api/*` ทั้งหมด (เว็บกลับไปเป็นแบบไม่ต้องล็อกอิน) ใช้ตอนที่ด่านไปขวางของที่ยิงเข้ามาจากนอกหน้าเว็บ |
| `AUTH_PUBLIC_API` | ทางออกฉุกเฉิน | รายชื่อเส้น API ที่ให้ผ่านโดยไม่ต้องมีตั๋ว คั่นด้วยจุลภาค เช่น `/api/stock-gas,/api/qcrd-gas` |

## ข้อจำกัดที่รู้อยู่

- **เตะคนออกทันทีไม่ได้** — ตั๋วที่ออกไปแล้วเรียกคืนไม่ได้ ปิดบัญชีตอนเจ้าตัวล็อกอินค้างอยู่
  เขายังใช้ต่อได้จนตั๋วหมดอายุ (12 ชม. — `SESSION_TTL_SECONDS` ใน `lib/authToken.js`)
- **กันเดารหัสผ่านได้แค่หลวม ๆ** — ตัวนับความพยายามอยู่ในหน่วยความจำของ container ซึ่ง Vercel
  ปลุก-ดับตลอด จะเอาจริงต้องไปทำที่ Vercel WAF / Cloudflare
- **`branch_code` ยังไม่ได้ใช้กรองข้อมูล** — ผูกบัญชีกับสาขาได้ แต่หน้าเว็บยังไม่ได้เอาไปกรอง
  คนที่ผูกสาขา SJP ไว้ยังเห็นยอดทุกสาขาในเมนูที่ได้สิทธิ์
- **สิทธิ์ละเอียดกว่าระดับเมนูยังไม่มี** — ยังแยก “ดูได้แต่แก้ไม่ได้” ไม่ได้

## เพิ่มเมนูใหม่ในอนาคต

เติมคีย์ใหม่ใน `MENU_GROUPS` ที่ `lib/permissions.js` ที่เดียว แล้วเมนูจะโผล่ทั้งในแถบข้าง
และในช่องติ๊กสิทธิ์พร้อมกัน (แถบข้างวาดจากทะเบียนตัวนี้ตรง ๆ) จากนั้นค่อยไปเพิ่ม
ไอคอนใน `MENU_ICONS` และตัวเรนเดอร์เนื้อหาที่ `pages/index.js`
คีย์ที่ยังไม่ได้ลงทะเบียนถือว่า “ไม่ได้คุมสิทธิ์” — จะเห็นได้ทุกคน
