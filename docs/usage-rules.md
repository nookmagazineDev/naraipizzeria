# ยอดใช้จากระบบ (หน้านับสต๊อกและขอเบิก) — กติกาการคำนวณ

หน้านับสต๊อกช่อง **"ยอดใช้จากระบบ"** ไม่ได้อ่านตัวเลขจากที่ไหนสำเร็จรูป แต่คิดสดทุกครั้งจาก

    ยอดใช้ (หน่วยซื้อ) = จำนวนเมนูที่ขายจริง × ยอดใช้ต่อจานตามสูตร BOM ÷ ตัวแปลงหน่วย

* ยอดขายจริง = `ctranbetweendate` (บรรทัดขายระดับไอเทมจาก POS) ของสาขานั้น
* สูตร BOM = แท็บ BOM ของชีท QC/RD หรือตาราง `dbo.qcrd_bom` (แล้วแต่โหมด — ดู `lib/qcrdSource.js`)
* โค้ด: `pages/api/usage-bom.js` (ยอดรวม + แยกเมนู) · `pages/api/usagebytable.js` (แยกโต๊ะ)
* กติกาทั้งหมดอยู่ที่เดียวใน **`lib/usageRules.js`** — สอง API ต้องใช้ชุดเดียวกันเสมอ
  ถ้ากรองต่างกันแม้แต่ข้อเดียว ผลรวมรายโต๊ะจะไม่เท่ากับยอด "ขาย" ของเมนูนั้นอีก

กติกาชุดนี้พอร์ตมาจาก `office-server/server.js` ของโปรเจกต์ **Narai-branch** (หน้านับสต๊อกที่สาขาใช้)
เพื่อให้ตัวเลขสองระบบตรงกัน

## แถวขายที่นับ

| กฎ | ค่าเริ่มต้น | env |
|---|---|---|
| ข้ามรายการที่ยกเลิก (`void`) | เสมอ | — |
| ข้ามโต๊ะเตรียมของ | โต๊ะ 600 | `USAGE_EXCLUDE_TABLES` |
| ข้ามไอเทมที่ไม่ใช่เมนูขายจริง | 500017, 500018 (เตรียมแป้งพิซซ่า S/M) | `USAGE_EXCLUDE_ITEMCODES` |
| วันที่ที่ยอดใช้ไปตกอยู่ | `PostTime` (เวลาที่ POS โพสต์รายการ) | — |

## กฎกันนับซ้ำ (สองข้อนี้คือตัวที่เคยขาดไป ทำให้ยอดใช้เนื้อสูงกว่าหน้าของสาขา)

1. **เมนูชั่ง (กก)** — ช่วงไหนมีเมนูที่ชื่อมี `(กก` ขายอยู่ วัตถุดิบของเมนูนั้นจะ **นับจากเมนู (กก) อย่างเดียว**
   เมนูอื่นที่ใช้วัตถุดิบตัวเดียวกันไม่นับ เพราะยอดขายของเมนู (กก) คือน้ำหนักที่ชั่งจริง — เป็นเนื้อก้อนเดียวกัน
2. **เมนูหน่วยจาน (ที่)** — วัตถุดิบใน `USAGE_EXCLUDE_PLATE_MENU_INGREDIENTS` (ค่าเริ่มต้น 11010081 สันคอหมู)
   ไม่นับจากเมนูที่ชื่อมี `(ที่)` หรือรหัสอยู่ใน `USAGE_EXCLUDE_PLATE_MENU_CODES`
   (ค่าเริ่มต้น 102001 สันคอหมูสไลด์, 180007 สันคอหมูอนามัยสไลซ์)

## จุดที่ตั้งใจให้ต่างจาก Narai-branch

* **ธง "ไม่ตัด BOM"** (คอลัมน์ T ของชีท / `no_deduct`) — ฝั่งนี้ยังเคารพอยู่ คือแถวสูตรที่ติ๊กไว้
  จะคิดเป็นต้นทุนตามปกติแต่ไม่ตัดสต๊อก ส่วน Narai-branch ไม่รู้จักธงนี้ (เขียนไว้ก่อนมีฟีเจอร์)
  จำนวนแถวที่ติดธงดูได้จาก `meta.bomRowsNoDeduct` ในคำตอบของ API
* **ช่อง "ขาย" แยกเมนู** — ฝั่งนี้ยุบสูตรที่ใช้วัตถุดิบตัวเดียวกันหลายบรรทัดให้เหลือตัวเดียวก่อนนับ
  (Narai-branch บวกซ้ำตามจำนวนบรรทัด เคยทำให้เมนู P20 ขึ้น "ขาย" 451 ทั้งที่ผลรวมรายโต๊ะ 225.5)
  **ปริมาณที่ใช้เท่ากันทั้งสองแบบ** ต่างแค่ตัวเลขในช่อง "ขาย"
* **ตัวแปลงหน่วยว่าง** — ฝั่งนี้ใช้ค่าเริ่มต้น 1000 (ให้ตรงกับตอนคิดต้นทุนใน `qcrd-apps-script.gs`)
  ส่วน Narai-branch ข้ามแถวนั้นทิ้ง จำนวนแถวแบบนี้ดูได้จาก `meta.bomRowsNoConverter`

## เวลาเลขไม่ตรงกับหน้าของสาขา

เรียก API ตรง ๆ แล้วดู `meta.rules` ซึ่งบอกกติกาที่ใช้จริงในรอบนั้น รวมถึงวัตถุดิบที่โดนกฎ (กก) ตัด:

    /api/usage-bom?branch=sjp&outletId=7&startDate=2026-09-01&endDate=2026-09-07

ถ้าต้องการกลับไปใช้กติกาเดิมของฝั่งนี้ (ตัดไอเทมเตรียมของทั้งช่วง 500002-500026 รวม 206001, 290016)
ตั้ง env บน Vercel แล้ว redeploy:

    USAGE_EXCLUDE_ITEMCODES=206001,290016,500002,500003,...,500026
