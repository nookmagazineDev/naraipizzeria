# เพิ่มเมนูจากฐานข้อมูลของ POS ตัวอื่น (QC/RD > เมนู)

ปุ่ม **“เพิ่มจากฐานข้อมูล”** บนหน้า QC/RD > เมนู ดึงทะเบียนเมนูจาก POS อีกสามฐานที่อยู่บน
SQL Server เครื่องเดียวกับ `InventoryNarai` มาให้เลือก แล้วบันทึกเข้าทะเบียนเมนูหลัก
(`dbo.qcrd_menu` หรือชีท `menu` แล้วแต่ `QCRD_SOURCE`) ไว้ใช้ทำสูตรและคิดต้นทุนต่อ

| ต้นทาง | ตาราง | ตัวนำหน้ารหัสตอนบันทึก |
|---|---|---|
| Aoringo (เฟรนไชส์) | `Aoringo.dbo.MenuItem` | `AO` |
| HumlaiPOS | `HumlaiPOS.dbo.Menu` | `HM` |
| NaraiPos (POS ของนารายณ์) | `NaraiPos.dbo.Item` | ไม่เติม — ใช้รหัสเดิม |

ตั้งชื่อฐาน/ตารางทับได้ด้วย env บนเครื่องโฮสต์ ถ้าเครื่องไหนตั้งชื่อไม่เหมือนกัน:
`AORINGO_DB_NAME` · `AORINGO_MENU_TABLE` · `HUMLAI_DB_NAME` · `HUMLAI_MENU_TABLE` ·
`POS_DB_NAME` · `POS_MENU_TABLE`

## ⚠️ ผลต่อรายงานยอดใช้วัตถุดิบ — อ่านก่อนเพิ่มเมนู

ระบบจับคู่เมนูกับยอดขายด้วย `menu_key` (รหัสเมนูที่ตัด 0 นำหน้าและทำเป็นตัวพิมพ์เล็ก)
เทียบกับเลขไอเทมที่ POS ของนารายณ์ส่งมาในบิล ดังนั้น:

* เมนูที่รหัสขึ้นต้นด้วย **`AO` / `HM` จะไม่มีวันจับคู่กับยอดขายได้** — เป็นเมนูไว้ทำสูตร
  และคิดต้นทุนเท่านั้น ไม่โผล่ในรายงานยอดใช้วัตถุดิบ/ต้นทุนต่อหัว
* เมนูจาก **`NaraiPos.dbo.Item` ที่ไม่เติมตัวนำหน้า จับคู่ได้ตามปกติ** — ซึ่งเป็นเหตุผลที่
  ต้นทางนี้ห้ามเติมตัวนำหน้าเด็ดขาด

## เส้นทางข้อมูล

```
หน้าเว็บ (components/QcRdMenu.jsx → MenuSourcePicker)
  └─ GET /api/qcrd-menu-source?src=…&q=…      อ่านอย่างเดียว ไม่ต้องมีกุญแจ
       └─ lib/qcrdSource.js  ต่อ SQL ตรงก่อน → ต่อไม่ติดถอยไป host API
            ├─ ตรง   : lib/qcrdPool.js (runQuery)  ─┐
            └─ host  : GET /qcrd/menu-source        ─┴─ ตรรกะเดียวกัน: lib/menuSourceSql.mjs

บันทึก: POST /api/qcrd-save { action: 'saveMenu', … }   ← ทางเดิมของปุ่ม "เพิ่มเมนู"
```

บันทึก **ทีละเมนูตามลำดับ** ไม่ใช่ยิงก้อนเดียว เพราะถ้าพลาดกลางทางต้องบอกได้ว่าเมนูไหน
เข้าแล้วเมนูไหนยัง และการใช้ `saveMenu` ตัวเดิมทำให้ได้ทั้งโหมดชีทและโหมด SQL โดยไม่ต้อง
เปิดทางเขียนใหม่ให้ต้องดูแลอีกชุด

## ไม่ฮาร์ดโค้ดชื่อคอลัมน์

สามฐานนี้เป็นของคนละแอป ไม่มีใครรับประกันว่าคอลัมน์รหัสชื่อ `Code` เหมือนกันหมด และเดาผิด
จะได้ตารางว่างเปล่าแบบไม่มีอะไรฟ้อง `lib/menuSourceSql.mjs` จึงอ่าน `INFORMATION_SCHEMA`
ตอนรันแล้วจับคู่ชื่อคอลัมน์จากรายการที่เป็นไปได้ (แบบเดียวกับ `lib/aoringoSql.mjs` ของฝั่งเฟรนไชส์)

ดูว่าจับคู่ได้อะไรบ้าง — เปิดจากเบราว์เซอร์ที่เครื่องออฟฟิศ:

```
http://localhost:14365/qcrd/menu-source-schema
```

ได้ทีละต้นทางว่า `ok` ไหม จำนวนแถวทั้งตาราง และ `map` ว่าช่อง code/name/price/group/status
ไปตกที่คอลัมน์ไหน ถ้าจับผิดตัวให้เพิ่มชื่อคอลัมน์ลงใน `FIELDS` ของไฟล์นั้น (เรียงจากน่าจะใช่ที่สุด)

## สิทธิ์ที่ต้องมี

host-server ต่อ SQL ด้วย login เดียว แล้วอ่านข้ามฐานด้วยชื่อสามท่อน `[ฐาน].[dbo].[ตาราง]`
login นั้นจึงต้องมีสิทธิ์อ่านครบทั้งสามฐาน ไม่งั้นแท็บนั้นจะขึ้นว่าอ่านไม่ได้ (แท็บอื่นยังใช้ได้)

```sql
-- รันที่เครื่องออฟฟิศด้วย sa — เปลี่ยน @login ให้ตรงกับที่ host-server ใช้
DECLARE @login SYSNAME = N'narai_app';

USE Aoringo;    IF DATABASE_PRINCIPAL_ID(@login) IS NULL CREATE USER [narai_app] FOR LOGIN [narai_app];
                ALTER ROLE db_datareader ADD MEMBER [narai_app];
USE HumlaiPOS;  IF DATABASE_PRINCIPAL_ID(@login) IS NULL CREATE USER [narai_app] FOR LOGIN [narai_app];
                ALTER ROLE db_datareader ADD MEMBER [narai_app];
USE NaraiPos;   IF DATABASE_PRINCIPAL_ID(@login) IS NULL CREATE USER [narai_app] FOR LOGIN [narai_app];
                ALTER ROLE db_datareader ADD MEMBER [narai_app];
```

ให้แค่ `db_datareader` พอ — ทางนี้ไม่เขียนอะไรลงฐานต้นทางเลย

## อาการที่เจอได้ + ทางแก้

| อาการ | แปลว่า | แก้ |
|---|---|---|
| `ยังไม่มีเส้น /qcrd/menu-source` | host-server ยังเป็นเวอร์ชันก่อนหน้านี้ | ที่เครื่องออฟฟิศ `git pull` แล้ว `host-server\start-narai.ps1 -Restart -NoTunnel` |
| `ไม่พบตาราง HumlaiPOS.dbo.Menu` | ฐานนั้นอยู่คนละ SQL instance หรือ login ไม่มีสิทธิ์ | ให้สิทธิ์ตามด้านบน · ถ้าคนละ instance ต้องเพิ่ม pool แยก (ยังไม่รองรับ) |
| `หาคอลัมน์รหัสไม่เจอ` | ชื่อคอลัมน์ไม่อยู่ในรายการที่รู้จัก | เปิด `/qcrd/menu-source-schema` ดูชื่อจริง แล้วเพิ่มลง `FIELDS` |
| ตารางว่างทั้งที่ฐานมีข้อมูล | เมนูถูกปิดในต้นทางทั้งหมด | ติ๊ก “แสดงเมนูที่ปิดในต้นทางด้วย” |
| ขึ้น “มีในระบบแล้ว” ทั้งที่ยังไม่เคยเพิ่ม | รหัสชนกับเมนูเดิม (เทียบแบบมองข้าม 0 นำหน้า) | ตรวจรหัสในทะเบียนก่อน — ระบบกันบันทึกทับให้โดยตั้งใจ |

## ข้อจำกัดที่ยังเป็นอยู่

* ดึงมาแค่ **รหัส · ชื่อ · ราคา** เท่านั้น หมวดหมู่ให้เลือกตอนกดบันทึก (ทั้งชุดลงหมวดเดียวกัน)
* เมนูที่เพิ่มเข้ามา **ยังไม่มีสูตร (BOM)** ต้องกดที่แถวในตารางแล้วใส่วัตถุดิบเอง
* ค้นหาได้สูงสุด 100 รายการต่อครั้ง (ค้นที่ฝั่ง SQL) — ตารางเมนูของ POS มีหลักพันแถว
  และทางกลับต้องผ่าน tunnel ของเครื่องที่ร้าน จึงไม่ลากทั้งตารางมาให้หน้าเว็บกรองเอง
