# เพิ่มวัตถุดิบจากฐานข้อมูล (QC/RD > วัตถุดิบ)

ปุ่ม **“เพิ่มจากฐานข้อมูล”** บนหน้า QC/RD > วัตถุดิบ ดึง **ของที่มีอยู่จริงในข้อมูลที่ใช้งานอยู่**
แต่ยังไม่มีในทะเบียนวัตถุดิบ มาให้เลือกเพิ่มเข้าทะเบียน — ไม่ต้องพิมพ์รหัส/ชื่อเองให้เสี่ยงพิมพ์ผิด

ต่างจากปุ่มชื่อเดียวกันของหน้าเมนู ตรงที่ต้นทางทั้งหมด **อยู่ในฐาน `InventoryNarai` ฐานเดียว
กับทะเบียนวัตถุดิบ (`dbo.stock_item`) เอง** ไม่ได้ข้ามไปฐานของ POS ตัวอื่น

| ต้นทาง | ตาราง | คือของอะไร |
|---|---|---|
| สูตรเมนู (ค่าเริ่มต้น) | `dbo.qcrd_bom` | วัตถุดิบที่สูตรในหน้าเมนูใช้อยู่จริง แต่ไม่มีในทะเบียน |
| แพลนสั่งของ | `dbo.stock_plan` | ของที่สาขาสั่งจริง แต่ไม่มีในทะเบียน |
| ปิดรอบสิ้นเดือน | `dbo.stock_closing` | ของที่สาขานับและปิดยอดจริง แต่ไม่มีในทะเบียน |

ทั้งสามตารางเก็บ `item_key` (รหัสที่ตัด 0 นำหน้า) ไว้จับคู่กับ `stock_item` อยู่แล้ว
การคัด “ตัวที่ยังไม่มีในทะเบียน” จึงทำด้วย `NOT EXISTS` ที่ฝั่ง SQL — ไม่ลากทั้งตารางกลับมา
ให้หน้าเว็บกรองเอง (`stock_plan` มีหลักหมื่นแถว และทางกลับต้องผ่าน tunnel ของเครื่องที่ร้าน)

## แต่ละต้นทางให้ค่าอะไรมาบ้าง

| ช่อง | สูตรเมนู | แพลนสั่งของ | ปิดรอบสิ้นเดือน |
|---|---|---|---|
| รหัส · ชื่อ | ✓ | ✓ | ✓ |
| หน่วยซื้อ | — | ✓ (ที่สั่งครั้งหลังสุด) | ✓ (ที่ปิดยอดครั้งหลังสุด) |
| ราคา | ✓ (ราคาที่บันทึกไว้ในสูตร) | ✓ `unit_price` | ✓ `unit_value` |
| ตัวแปลงหน่วย | ✓ | — | — |
| ประเภท | ✓ (แท็กในสูตร) | — | — |
| คอลัมน์ “เจอที่ไหน” | ใช้ในกี่เมนู | สั่งกี่ครั้ง + วันล่าสุด | ปิดยอดกี่ครั้ง + วันล่าสุด |

ช่องที่ต้นทางไม่มี (สาขาที่ใช้ · หมวดสโตร์ · itemID ของ POS · **หน่วยใช้**) เว้นว่างไว้เสมอ
แล้วไปกรอกต่อในฟอร์ม — ไม่เดาค่าให้ เพราะเดาผิดแล้วไม่มีอะไรฟ้อง

## สองวิธีเพิ่ม — เลือกได้ในหน้าต่างเดียวกัน

| ทำอะไร | ได้อะไร | เหมาะกับ |
|---|---|---|
| **กดที่แถว** | ปิดหน้าต่างแล้วเปิดฟอร์มเพิ่มวัตถุดิบที่กรอกรหัส/ชื่อ/หน่วย/ราคา/ตัวแปลงให้แล้ว **ยังไม่บันทึกจนกว่าจะกดบันทึกในฟอร์ม** | เพิ่มทีละตัวแล้วเลือกสาขา/หน่วยใช้ให้ครบไปเลย |
| **ติ๊กช่องซ้าย + ปุ่มบันทึก** | บันทึกหลายตัวรวดเดียว ทุกตัวยังไม่มีสาขา/หน่วยใช้ ค่อยกด “แก้ไข” มาใส่ทีหลัง | ยกของเข้าทะเบียนก่อน ค่อยทยอยกรอกรายละเอียด |

บันทึก **ทีละรายการตามลำดับ** ไม่ใช่ยิงก้อนเดียว เพราะถ้าพลาดกลางทางต้องบอกได้ว่าตัวไหน
เข้าแล้วตัวไหนยัง และการใช้ action `addItem` ตัวเดิมทำให้ได้ทั้งโหมดชีทและโหมด SQL
โดยไม่ต้องเปิดทางเขียนใหม่ให้ต้องดูแลอีกชุด

## เส้นทางข้อมูล

```
หน้าเว็บ (components/QcRdItems.jsx → ItemSourcePicker)
  └─ GET /api/qcrd-item-source?src=…&q=…      อ่านอย่างเดียว ไม่ต้องมีกุญแจ
       └─ lib/qcrdSource.js  ต่อ SQL ตรงก่อน → ต่อไม่ติดถอยไป host API
            ├─ ตรง   : lib/qcrdPool.js (runQuery)  ─┐
            └─ host  : GET /qcrd/item-source        ─┴─ ตรรกะเดียวกัน: lib/itemSourceSql.mjs

บันทึก: POST /api/qcrd-save { action: 'addItem', … }   ← ทางเดิมของปุ่ม "เพิ่มวัตถุดิบ"
```

## ⚠️ โหมดชีทกับโหมด SQL กรองคนละชั้น

ตัวกรอง `NOT EXISTS` ที่ฝั่ง SQL เทียบกับ **`dbo.stock_item`** เสมอ

* โหมด `QCRD_SOURCE=sql` (ที่ใช้อยู่จริงตอนนี้) — `stock_item` คือทะเบียนตัวจริง ตรงกันพอดี
* โหมดชีท — ทะเบียนตัวจริงคือชีท `item` ส่วน `stock_item` เป็นของที่ถูก “ดันขึ้น SQL” ไว้
  จึงอาจไม่ตรงกันเป๊ะ หน้าเว็บเลยกรองซ้ำด้วยรายการที่โหลดมาจริงอีกชั้น (`existingKeys`)
  และบอกท้ายหน้าต่างว่าซ่อนตัวที่มีในทะเบียนแล้วไปกี่ตัว

## อาการที่เคยเจอ / ต้องแก้ตรงไหน

| ขึ้นว่า | แปลว่า | แก้ยังไง |
|---|---|---|
| `ยังไม่มีเส้น /qcrd/item-source` | host-server ยังเป็นเวอร์ชันก่อนหน้านี้ | ที่เครื่องออฟฟิศ `git pull` แล้ว `host-server\start-narai.ps1 -Restart -NoTunnel` |
| `ไม่พบตาราง dbo.stock_plan` | ฐานนี้ยังไม่ได้รัน `docs/schema-sheets.sql` | รันไฟล์สคีมานั้นก่อน (ต้นทางอื่นยังใช้ได้ตามปกติ) |
| แท็บขึ้น `• อ่านไม่ได้` ทั้งสามอัน | ต่อฐานไม่ติดเลย ไม่ใช่ปัญหาของต้นทางใดต้นทางหนึ่ง | ดู `/api/qcrd?debug=1` ว่าทางไหนใช้อยู่ แล้วไล่ต่อจากตรงนั้น |
| ต้นทางว่าง “ครบแล้ว” | ไม่มีรหัสไหนในต้นทางที่ยังไม่มีในทะเบียน | ปกติ — ไม่ใช่ข้อผิดพลาด |
