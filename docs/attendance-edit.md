# แก้เวลาสแกนนิ้วจากหน้า "ดูสแกนหน้า"

> **คำตอบสั้น ๆ:** ในตารางสรุปรายวัน คลิกที่ช่องเวลาฝั่ง **สแกนจริง** (เข้า / ออกเบรค / เข้าเบรค / ออก)
> ได้เลย กรอกเวลาใหม่แล้วกด ✓ — การกดบันทึกแต่ละครั้งเป็น **การบันทึกรายการใหม่**
> ลงตาราง `InventoryNarai.dbo.attendance_edit` ไม่ได้เขียนทับข้อมูลของเครื่องสแกน

## ทำไมต้องแก้ได้

เวลาสแกนจริงมีวันที่ใช้ไม่ได้อยู่เรื่อย ๆ — พนักงานลืมสแกนตอนออก, เครื่องรับนิ้วซ้ำสองครั้ง
จนกลายเป็นเบรคที่ไม่มีจริง, หรือมาสแกนช้าเพราะต่อคิว เวลาพวกนี้เป็นฐานคิดค่าแรง
ถ้าแก้ไม่ได้ก็ต้องไปนั่งแก้ในไฟล์ Excel ทีหลังทุกเดือน

## แก้แล้วข้อมูลไปอยู่ไหน

```
เบราว์เซอร์ -> POST /api/attendance-edit -> (ต่อ SQL ตรง | host API /sheets/save)
                                         -> InventoryNarai.dbo.attendance_edit   (INSERT เท่านั้น)
```

* **ZKBio9 ไม่ถูกแตะเลย** — ตาราง `dbo.iclock_transaction` ของเครื่องสแกนยังอ่านอย่างเดียวเหมือนเดิม
  เครื่องสแกนส่งข้อมูลเข้ามาใหม่ก็ไม่ทับสิ่งที่แก้ไว้
* **บันทึกใหม่ทุกครั้ง ไม่แก้ทับ** — กดแก้ช่องเดิมสิบรอบก็ได้สิบแถว เวลาที่หน้าเว็บใช้คือแถวล่าสุด
  ของช่องนั้น (คัดด้วย `ROW_NUMBER` ตอนอ่าน) ที่เหลือเก็บไว้เป็นประวัติว่าใครแก้จากเท่าไหร่เป็นเท่าไหร่เมื่อไหร่
* **ชั่วโมงทำงานกับนาทีที่สายคิดใหม่ให้** จากเวลาชุดที่แก้แล้ว (`applyScanEdits` ใน `lib/attendance.js`)
  ตัวเลขในแถวจึงตรงกับเวลาที่เห็นเสมอ และไฟล์ Excel มีคอลัมน์ `แก้ไขเวลา` บอกว่าช่องไหนไม่ใช่ของเครื่องสแกน
* **เว้นว่างไว้ = ลบเวลาช่องนั้น** (เก็บเป็น `NULL`) ใช้กับกรณีเครื่องรับนิ้วซ้ำจนได้เบรคปลอม

ช่องที่ถูกแก้จะเป็นพื้นเหลืองมีดินสอ ชี้เมาส์ค้างไว้จะเห็นว่าเดิมคือเวลาอะไร ใครแก้ เมื่อไหร่

## ต้องเตรียมอะไรก่อนใช้

1. **สร้างตาราง** `dbo.attendance_edit` — อยู่ในไฟล์เดียวกับตารางชุดอื่น
   [`schema-sheets.sql`](schema-sheets.sql) เลือกทางใดทางหนึ่ง
   * จากหน้าเว็บ: `/api/sheets-migrate?key=<SHEETS_MIGRATE_KEY>&step=schema&confirm=1`
     (เช็กก่อนได้ด้วย `&step=check` — จะเห็น `attendance_edit: true/false`)
   * ที่เครื่องออฟฟิศ: `sqlcmd -S localhost\SQLEXPRESS -U sa -P '<รหัส>' -i docs\schema-sheets.sql`
2. **เปิดทางเขียน** — เหมือนหน้าค่าใช้จ่ายอื่น ๆ ที่เขียนลง `InventoryNarai`
   * ต่อ SQL ตรงได้: ตั้ง `QCRD_DB_USER` / `QCRD_DB_PASSWORD` (หรือ `ZK_DB_*` / `HR_DB_*`) บน Vercel
   * ต่อตรงไม่ได้ (สถานะปัจจุบันของร้าน): ตั้ง `SHEETS_WRITE_KEY` (หรือ `QCRD_WRITE_KEY`)
     บน Vercel ให้ตรงกับที่ตั้งไว้บนเครื่องออฟฟิศ แล้วรีสตาร์ท `host-server` ให้เป็นเวอร์ชันที่มี
     `/sheets/scan-edit` (git pull แล้ว `node server.js`)

ยังไม่ได้ทำสองข้อนี้ หน้าเว็บก็ยังใช้ได้ตามปกติ — จะขึ้นแถบสีเหลืองบอกว่าอ่าน/บันทึกตัวแก้ไม่ได้
แล้วแสดงเวลาดิบจากเครื่องสแกนเหมือนเดิม

## API

| คำสั่ง | ทำอะไร |
|---|---|
| `GET /api/attendance-edit?start=&end=[&branch=]` | เวลาที่แก้ไว้ในช่วงนั้น (แถวล่าสุดของแต่ละช่อง) |
| `GET /api/attendance-edit?date=&emp=&history=1` | ประวัติการแก้ของคนหนึ่งในวันหนึ่ง ทุกครั้งที่กดบันทึก |
| `POST /api/attendance-edit` | บันทึกใหม่หนึ่งช่อง — `{ date, empCode, slot, time, oldTime?, name?, branch?, note? }` |

`slot` = `in` \| `breakOut` \| `breakIn` \| `out` · `time` = `'HH:mm'` หรือ `''` (ล้างค่า)

ฝั่งเครื่องออฟฟิศเปิดเป็น `GET /sheets/scan-edit`, `GET /sheets/scan-edit-history`
และ `POST /sheets/save { action: 'saveScanEdit', ... }` (ต้องมี `x-api-key`)
