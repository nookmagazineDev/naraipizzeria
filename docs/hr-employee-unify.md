# รวมรายชื่อพนักงานให้เหลือตารางเดียว

## ก่อนหน้านี้มีสามที่

| ใช้ที่ไหน | อ่านจาก | หมายเหตุ |
|---|---|---|
| หน้ารายชื่อพนักงาน (รีโปนี้) | `InventoryNarai.dbo.hr_employee` | มี `start_date`, `loga`, `new_code`, `photo_url`, `sort_order` |
| ดรอปดาวน์ผู้นับสต๊อก/ผู้เบิก (รีโปนี้) | Google Sheet ผ่าน Apps Script | คนละชุดกับสองอันข้างบน |
| ตารางงาน · ประวัติกะ (Narai-branch) | `narai_hr.dbo.hr_employee` | มี `daily_wage`, `resign_date` · `hr_timesheet` อ้าง `hr_code` ตารางนี้ |

เพิ่มพนักงานที่หน้าหนึ่ง อีกสองหน้าไม่เห็น และชื่อในดรอปดาวน์ก็ไม่ตรงกับรายชื่อจริง

## ตอนนี้เหลือที่เดียว: `narai_hr.dbo.hr_employee`

เลือกฐานนี้เพราะตารางงานกับประวัติกะผูกกับ `hr_code` ของฐานนี้อยู่แล้ว
ย้ายทางกลับกันจะต้องรื้อฝั่ง Narai-branch ทั้งระบบ

ทั้งสามทางข้างบนอ่าน/เขียนตารางนี้หมดแล้ว และหน้ารายชื่อพนักงานแก้ได้ครบทุกคอลัมน์
ยกเว้นสองตัวที่กันไว้โดยตั้งใจ

- `hr_code` เป็นคีย์ — ตารางงาน/ประวัติกะอ้างรหัสนี้ เปลี่ยนแล้วประวัติจะขาดจากคน
- `updated_at` ฐานตั้งเวลาให้เองทุกครั้งที่บันทึก

## ต้องทำอะไรบ้าง (ตามลำดับ)

### 1. รันสคริปต์ที่เครื่องออฟฟิศ — ครั้งเดียว

เปิด SSMS ด้วย `sa` แล้วรัน `docs/schema-hr-employee.sql` ทั้งไฟล์ สคริปต์นี้จะ

1. เติมคอลัมน์ที่ `narai_hr` ยังไม่มี (`start_date`, `loga`, `new_code`, `photo_url`, `sort_order`)
2. ขยายความกว้าง `full_name` / `emp_type` / `status` ให้รับข้อมูลฝั่งเก่าได้
3. สำรองตารางทั้งสองฝั่งไว้ (`hr_employee_backup_premerge`)
4. ย้ายข้อมูลจาก `InventoryNarai` มารวม — ยึดค่าฝั่ง `narai_hr` สำหรับชื่อ/สาขา/ตำแหน่ง/สถานะ
   เพราะฝั่งนั้นถูกอัปเดตทุกสัปดาห์ผ่านหน้าลงตารางงาน · คนที่มีเฉพาะฝั่งเก่าจะถูกเพิ่มเข้ามาทั้งแถว
   (อยากให้ฝั่งเก่าชนะแทน มีบรรทัดให้สลับอยู่ในสคริปต์)
5. พิมพ์ยอดออกมาให้เทียบว่าครบไหม

รันซ้ำได้ ไม่พังถ้ารันไปแล้ว และไม่มีคำสั่งลบใคร

### 2. ให้สิทธิ์ login ที่เว็บใช้ในฐาน `narai_hr`

หน้าเว็บต่อ SQL ตรงด้วย login เดียวกับ QC/RD (`QCRD_DB_USER` / `ZK_DB_USER` / `HR_DB_USER`)
ถ้ายังไม่เคยให้สิทธิ์ในฐานนี้ จะต่อติดแต่ query ไม่ผ่าน ขึ้นว่า *is not able to access the database*
คำสั่งให้สิทธิ์อยู่ท้าย `docs/schema-hr-employee.sql`

เช็กว่าผ่านหรือยัง: เปิดหน้ารายชื่อพนักงาน ถ้าขึ้นรายชื่อครบคือเรียบร้อย

### 3. อัปเดต host-server ที่เครื่องออฟฟิศ (เฉพาะกรณีที่ยังใช้ทางนี้)

`git pull` แล้วรีสตาร์ท — จะได้ endpoint ใหม่ `/hr/employee`, `/hr/schedule-employees`, `/hr/save`, `/hr/ping`
ทางนี้เป็นทางถอยเวลา Vercel ต่อ SQL ตรงไม่ได้ เช็กว่าพร้อมไหมด้วย `http://localhost:14365/hr/ping`

> `/sheets/employee` ถูกปลดออกแล้ว (ชี้ไปตารางเก่า) — ใช้ `/hr/employee` แทน

### 4. อย่าเพิ่งลบตารางเก่า

เว้น `InventoryNarai.dbo.hr_employee` ไว้สัก 1-2 สัปดาห์ให้แน่ใจก่อน
แล้วค่อยเปลี่ยนชื่อกันเผลอเขียนซ้ำ (คำสั่งอยู่ท้ายสคริปต์)

## ⚠️ เรื่องที่ยังค้างอยู่ฝั่ง Narai-branch

ฝั่งนั้น **ยังใช้ Google Sheet เป็นตัวหลัก** ของรายชื่อพนักงาน แล้วซิงก์ลง `narai_hr` ให้อัตโนมัติ
ทุกครั้งที่มีคนเปิดหน้าตารางงาน (ดู `MIRROR_TO_SQL` ใน `src/services/api.js` ที่ยิง action
`syncEmployees` ของ `office-server/schedule.js`)

การซิงก์นั้นเขียนทับ 5 คอลัมน์นี้ด้วยค่าจากชีท

`full_name` · `branch` · `emp_type` · `position` · `daily_wage` (และตั้ง `status` เป็นทำงาน/ลาออก)

แปลว่าถ้าแก้ 5 ช่องนี้จากหน้ารายชื่อพนักงานของรีโปนี้ แล้วมีคนเปิดหน้าตารางงานของ Narai-branch
ค่าที่แก้จะถูกชีทเขียนทับกลับ ส่วนคอลัมน์ที่เหลือ (`start_date`, `loga`, `new_code`, `photo_url`,
`sort_order`, `resign_date`) ไม่โดน เพราะการซิงก์ไม่แตะ

**ให้ SQL เป็นตัวหลักจริง ๆ ต้องแก้ที่รีโป Narai-branch หนึ่งจุด** — ปิดการซิงก์จากชีททิ้ง

```js
// src/services/api.js
const MIRROR_TO_SQL = new Set([]);   // เดิมเป็น new Set(['getScheduleEmployees'])
```

แล้วเปลี่ยนหน้ารายชื่อพนักงาน/เพิ่มพนักงานของฝั่งนั้นให้ยิงเข้า SQL แทน Apps Script
(รีโปนี้ push ไปที่นั่นไม่ได้ จึงทำให้ไม่ได้)

ระหว่างที่ยังไม่ได้แก้: แก้ 5 ช่องนั้นที่ชีทเหมือนเดิม ส่วนช่องที่เหลือแก้จากหน้าเว็บนี้ได้เลย
